## 二、解密方式（结论）

镜像内 `device.toml` 明写：

```toml
[data]
weaver_first = true
```

即 **weaver 槽优先，gatekeeper 绑定的 blob 只作兜底**。

两条路径（源码 `crates/skyward-crypto/src/data.rs` 与主程序字符串核对一致）：

1. **weaver 路径（本版首选）**
   - `/data/system_de/<user>/…` 旁的 `<id>.weaver` 记录该用户在 eSE 里的槽号，`<id>.spblob` 是该槽包的密文；
   - 起 `android.hardware.weaver-service.nxp-qti`（NXP weaver），它经 **OMAPI** 打开 eSE 里的 applet 取槽 → 解 `.spblob`；
   - OMAPI 由 `se_omapi`（`android.se.omapi.ISecureElementService/default`）提供，weaver 的 `ese_weaver.so` 通过它的 reader 发 GetSlots。
2. **兜底路径（`weaver_first` 未开或 weaver 不可用）**
   - Android 给同一用户另留一份 blob，绑定在 `<id>.secdis` 的字节上，由 credential 服务（keymint + gatekeeper）用同一口令打开；skyward 取这一份，结果等价。

与 17（pudding）对照：pudding 主线走 blob（1.8–1.9 s），weaver 仅兜底；popsicle 这版显式反过来，因为它的 weaver 是 **NXP**（17 Ultra 是 Goodix）。

## 四、关键前提（不满足就解不开，均已在本镜像里做掉）

1. **secure_element 必须注册 `eSE1`**：TWRP 的 `recovery-device.xml` 声明 eSE1；缺了 servicemanager 会拒绝 HAL 的 addService，HAL 在 `main.cpp:608` abort，同时杀掉 NXP weaver 的通道（`ese_weaver.so` 走 `android.hardware.secure_element`），`/data` 锁死。
2. **se_omapi 必须有 VINTF 描述**：本镜像把 TWRP 的 `se_omapi.xml` 烘进 `/system/etc/vintf/manifest/se_omapi.xml`：
   ```xml
   <manifest version="9.0" type="framework">
     <hal format="aidl">
       <name>android.se.omapi</name>
       <fqname>ISecureElementService/default</fqname>
     </hal>
   </manifest>
   ```
   否则 servicemanager 不认这个接口，weaver 报 `Failed to start omapiSeService null`，`/data` 仍锁。
3. **不能用 vendor 自带的 `secure_element-service.xml` 顶替**：它把 name 与 instance 写在两个标签里，`secure::describes()` 匹配不到。
4. 主程序内留有对应报错串：`…is not running; the phone's weaver has to be started first` —— weaver 优先路径对启动顺序敏感。

## 六、与本地源（0.3.1）的差异

- 本地 `devices/popsicle.toml` 4,028 B，**没有** `[data]` 段、没有 weaver/OMAPI 服务；镜像内 `device.toml` 11,265 B，diff 185 行。
- 镜像 stock 基线换成 **OS4.0.6.0.XPBCNXM**（recovery sha256 `cfd845ae5b18812757ba83170d0dce690bb998d1310e7bc0b186e362be7ad9e5`）。
- device.toml 注释引用 `scripts/augment_stock.py`、`resources/popsicle/recovery-hal.zip`、`docs/PACK-IMAGE.md`、`docs/BUMP-STOCK.md` —— 本机没有这套 fork 工程，说明 v40 是外部 fork 在 Windows 上构建（cargo 路径 `C:\Users\F\`，rustc 1.100.0 / 2026-11-09）。
- 触感改动：Cirrus CS40L26（I2C 13-0043），补 cs40l26 固件到 `/lib/firmware`，主程序把 FF_CUSTOM 上传改成 FF_SINE（BUZZGEN 音），强度 0.15–1.0。

## 七、结论

popsicle v40 的解密可完整复原：**weaver-first（NXP weaver → OMAPI/se_omapi → eSE1 → keymint 解 spblob），gatekeeper/secdis 兜底**，依赖 eSE1 注册 + `se_omapi.xml` 入 VINTF + `nxp-nci` 模块 + 八个服务按序起来。这套链与我们在 pandora（17 Pro，同为 NXP weaver）上验证过的链一致，可直接移植到自建 popsicle 包。
